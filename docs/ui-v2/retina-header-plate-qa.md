# Header and plate visual-quality release gate
Scope: existing signed-in header, plate rendering, and visual QA only. No workflow, data, navigation, or financial changes.

- Keep the approved original 3840 × 2160 PNG byte-for-byte identical and use its lossless 3411 × 672 plate crop. At the largest default display width of 222 CSS px, 3× DPR requires 666 pixels, and 4× requires 888 pixels; the crop provides ample source detail. Do not upscale or sharpen artificially.
- Plate edges: 2% horizontal / 10.15% vertical proportional corner rounding (about 2.76 CSS px for compact). Keep the original aspect ratio so the image and vector overlay stay aligned. Render glyphs as SVG geometry at native device resolution. Compute layout once per render.
- Shared sapphire banner uses CSS gradient and the existing logo crop. No additional animated filters or background images. Maintain existing native scrolling and reduced-motion settings.
- QA all signed-in route families and all UKPlate call sites. Use 320/375/390/430/768/1280 CSS px viewports at DPR 1, 2, 3; additionally capture a 3840×2160 desktop image at native resolution. Inspect real screenshot pixels and overflow. Verify long/private/empty registrations, narrow glyphs, dark mode, portal operator branding, profile/back/actions, portrait/landscape and safe-area behavior.
- Performance acceptance: test on a physical 120 Hz-capable device, low-power mode off, with Safari/PWA and representative large job lists. Measure requestAnimationFrame intervals and browser performance traces while scrolling, navigating and interacting. Target 8.33 ms per frame at 120 Hz; record actual median and p95 intervals and dropped frames, not assumed refresh rate. Compare against baseline. Also test 60 Hz and reduced motion. Do not use setInterval to force 120fps or global will-change.
- A 4K screenshot is a capture dimension, not a guarantee of a 4K device screen. Retina UI uses native DPR; frame rate is controlled by hardware/browser/OS, and no CSS can guarantee sustained 120fps. CI tests do not prove physical-device performance.
- Do not mark the physical-device or actual browser visual gate passed until measured. No deployment is authorized by this quality-only revision.
